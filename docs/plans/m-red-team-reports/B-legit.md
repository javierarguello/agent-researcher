# B-legit — surface B (research loop `gather.ts` + evidence/handoffs in `research-engine.ts`) / LEGITIMATE-USER lens

## Verdict for the surface: held by accident
The bounds hold against the attacker's free-call loop only because they also cut into honest ones: the iteration cap `2·budget+6` gives every honest agent exactly 4 free calls of headroom regardless of budget, a researcher that uses `update_plan` the way the tool's own description asks (`doing`→`done`) is cut off before its allowance is spent on every comprehensive Florida agent, and a loop that spent 100% of its budget is still classed `stalled` (unreusable) if it had no iteration left to say "ready". Separately — bigger, and honest-only — the dossier's FIRST-14 pages of a store shared across ten agents means every producer after the first two writes from other agents' pages: the deal-scout sees 3 of its 12 fetched listings, the deep-dive-refiner sees 0 of its own.

Tests: `packages/core/test/red-team/b-legit.test.ts` (mock tier runs in ~0.5 s; the live case ran once, 562 s).

## Findings (most severe first)

### F1 · A producer's own fetched pages never reach its own writing prompt once the shared store holds 14 — the deep-dive-refiner's 10 paid fetches are rendered to nobody
- where: `packages/core/src/engine/prompt.ts:100-101, 159-161` (`MAX_SNIPPETS=48`, `MAX_PAGES=14`, `evidence.slice(0, …)`, `extracted.filter(ok).slice(0, MAX_PAGES)`) fed by the shared `evidence` store (`research-engine.ts:731-790`, same `evidence.extracted` for every agent, appended in fetch order; `maxConcurrentAgents=2`, template order market → competition → deal-scout → …).
- input: the real `florida-business-for-sale` template, comprehensive mode, honest fake web + 80 honest listing pages (no payloads), a modest honest model per producer: plan, then alternate `web_search` for a fresh listing / `fetch_page` of it, stop at the allowance.
- observed (own pages fetched → own pages in own dossier): market-analyst 4→4, competition-analyst 4→4, **deal-scout 12→3**, compliance-analyst 4→3, community-analyst 4→0, valuation-analyst 5→0, financial-analyst 3→0, risk-analyst 2→0, market-refiner 2→0, **deep-dive-refiner 5→0**. Store at the end: 45 pages / 47 sources; every writer past the third saw the same 14 pages (8 market/competition + 3 scout listings + 3 compliance). The refiner whose focus is "fetch_page listing URLs for details still marked n/a" writes `deep_dives` from a dossier holding 3 of the scout's 12 listing pages and none of its own re-reads/new fetches. Snippets were not capped in the fixture (5 results/search, 47 total); with Brave (`count=8`, `web-search.ts:66`) the market-analyst's 8 searches alone fill the 48 → reasoned: no deal-scout listing SNIPPET reaches its writer either.
- status: reproduced (`b-legit.test.ts::3 · … every Florida producer's own fetched pages reach its own writing prompt` — `it.fails`, i.e. red against the honest expectation, with the table printed). Snippet half: reasoned.
- refutation attempted: (i) `currentBlock` — the refiner gets its own `deep_dives` JSON whole, so figures already there survive; but new detail can only come from the dossier, and its new pages are not in it. (ii) The loop model saw the page (cached tool result) — but the loop writes nothing; the handoff/sections are written by the structured call that gets the dossier. (iii) `contextBlock` sections — carry other agents' prose, not page text. (iv) Checkpoint keeps the LAST 60 pages (`research-engine.ts:353`) while the dossier renders the FIRST 14: on a resume of a >60-page job the first-14 silently become pages 61–74; not triggered by a 92-turn Florida job (~45 pages), noted only.
- fix sketch: render OWN-first — the pages/snippets this loop touched (its fetches incl. cached hits, its search results) first, then the rest, still capped at 48/14. What a legit run loses if fixed naively as "most recent 14": the deep-dive-refiner still misses the scout's listings (a cached hit does not re-append), and the deal-scout loses the market pages it never needed. Under own-first nothing honest measured here is lost, and an attacker page only crowds the loop that fetched it (helps B-attack too).

### F2 · A researcher that marks each step `doing`→`done`, as the tool description asks, is cut off before spending its allowance on every comprehensive Florida agent; a researcher that cross-checks pages is classed unfinished after spending 100 %
- where: `gather.ts:180` (`maxIterations = maxTurns * 2 + 6`), `:200` (`stop = 'stalled'` default), `:246` (`budget|done` set only when the model gets an iteration to answer with no tools), `:374`; `research-engine.ts:755` (`gatherCompleted` → reuse on retry); the tool description `gather.ts:19-22` ("then again as you learn to mark steps done/doing").
- input: `DiligentResearcher` — one tool call per response, honest script driven only by the budget and `turnsLeft`/`stop`: initial plan; per turn `[plan doing] → search|fetch(distinct URL) → plan done`; optional cached re-read of the first page every 2nd fetch (the loop stubbed its body, `KEEP_FULL_PAGES=2`, and the kickoff says "cross-check key facts"); stops when told `Budget reached`.
- observed (turns spent / budget, stop): persona **revise** (one plan revision per result): fits everywhere, `budget`, reusable — its headroom is exactly 4 free calls whatever the budget (2B+2 vs 2B+6). Persona **doing→done**: comprehensive market/competition/compliance/community 7/8 `stalled`; deal-scout **18/24 stalled (6 turns, 25 %, never spent)**; valuation 8/10; financial 6/6 stalled; risk 5/5 stalled; market-refiner 5/5 stalled; deep-dive-refiner 8/10; essential deal-scout 10/12, valuation 5/5 stalled, deep-dive-refiner 5/5 stalled. Persona **revise+cross-check** deal-scout: **24/24 spent, `stalled`, unreusable** (6 re-reads = 54 iterations = cap; no iteration left to say "ready"). Adding doing→done+cross-check: deal-scout 16/24. Max consecutive free calls by any honest persona: 3.
- what it costs: (a) fewer listings/less evidence for the buyer (the deal-scout's shortlist is built from 18 turns, not 24); (b) `research.done=false` → a failed WRITE (the ordinary schema-validation failure) re-buys the whole loop: Florida-shaped scout (budget 8) with one bad write — revise persona: 1 research pass, "Reusing evidence already gathered", 4 search calls, $0.0026 loop+write LLM; doing→done persona: **2 passes, no reuse, 8 search calls, $0.0057** (2.2×), and 2× the loop's re-sent context.
- status: reproduced (`::1 · … measures every Florida agent under three honest personas` prints the table and asserts the deal-scout 24/24-stalled row; `::1 · … doing→done … spends its allowance and finishes — today: budget 8 → 7 turns/stalled, budget 24 → 18 turns/stalled` is `it.fails`; `::2 · … evidence is reused after a failed write … today it is re-bought` is `it.fails`). Live tier (qwen2.5:3b, one run): the small model UNDER-uses free calls (scout 0 plan updates, 1 search then stopped; refiner 1 plan, 1 search, 1 fetch) — the stall is a diligent-frontier-model behaviour, argued by the mock, not confirmed live.
- refutation attempted: a model batching `[update_plan, web_search]` in one response uses one iteration and never stalls — true for models that emit parallel calls; the loop cannot assume it (Ollama/qwen and Gemini in this loop emit one call per turn in the observed traces). The `Budget reached` pre-check (`gather.ts:322`) refuses cached re-reads after the allowance, so a model cannot "stall" by re-reading after budget — the stall is mid-loop only. `KEEP_FULL_PAGES=2` is what makes the re-read necessary; it is not the bug, the cap arithmetic is.
- fix sketch (2 lines): at loop exit, `if (stop === 'stalled' && turnsUsed >= maxTurns) stop = 'budget'` (a spent allowance IS the finished pass by the code's own comment) — no legit loss, and plan-spam's spent-budget loop becomes reusable, which is cheaper, not weaker; and replace the flat `2B+6` with a **consecutive-free-call breaker** (≥4 free calls in a row → `stop:true` "write with what you have"): every honest persona measured peaks at 3, plan-spam alternates free calls forever and would end in 4 iterations instead of 2B+6. What a naive fix costs: lowering `+6` or charging free calls (see F3).

### F3 · What the likely fixes cost an honest run (measured/reasoned)
- (a) charge a turn for `update_plan` / cached `fetch_page`: the revise persona makes B+1 plan updates (9 for B=8, 25 for B=24) — charged, an honest B=8 agent buys ~4 real searches/fetches, halving its evidence, and the tool description ("call this FIRST") makes the first charge unavoidable (33 % of an essential B=3 agent). Charged re-reads: the deal-scout's cross-check of 12 listings costs 6 of 24 turns; the deep-dive-refiner's whole job is re-opening scout pages (cached, free today) — charged, its 10 turns buy text the job already owns. reasoned from the table.
- (b) cap plan updates: honest revise = B+1, doing→done = 2B+1; any cap ≤ 2B+1 refuses honest updates; the plan is only ever the model's own scratchpad + a note (`gather.ts:254-258`) — the free-call-run breaker above is the cap that costs nothing honest. reasoned.
- (c) render evidence by recency: see F1 — recency does not restore the refiner's listing pages (cached hits do not re-append) and drops the market context from the scout; own-first does both jobs. reproduced (F1 table) + reasoned.
- (d) drop notes from `update_plan`: `Plan updated (n steps)` reaches the buyer's progress line (`JobView.tsx:76`) and the trace; dropping loses the only sign of life during planning; `MAX_NOTES=300` is never near for honest personas (deal-scout doing→done+cross-check: 34 plan + 24 tool notes = 58) nor for plan-spam (≤ 2×54). Sound either way; not a fix worth making.

## Checked and found sound (so nobody re-reports it)
- `MAX_HANDOFF_CHARS=1_500` (`prompt.ts:209`, `research-engine.ts:807-810`): live run, honest web, qwen2.5:3b — handoffs 286 / 303 / 434 chars, none cut. The 1,500 cap is ~250 words; the schema asks for "figures and names that matter" — six deep-dive targets × (name, price, revenue, SDE, lease) ≈ 700 chars fits. Not binding; a cut mid-sentence remains possible only for a verbose model and `splitHandoff` appends `…` (visible). reasoned + one live sample.
- Handoff JSON encoding is legible to a small model: the advisor wrote a coherent recommendation citing Bayside Wash Center at $280,000 (from the sections block; the scout's handoff itself carried NO figures — "details on two specific listings" — so the handoff added continuity, not numbers). Model quality notes, not surface findings: the 3b model wrote a bare `[S3]` tag against the directive and hallucinated a 2024 lease expiry (corpus says November 2027).
- Legit imperatives / link-following (task 5): the kickoff keeps "Read them for facts and follow links you judge useful" (`prompt.ts:371`) BEFORE the caveat, and the caveat is scoped to pages that "claim to be a system message" and to "the rest of your budget" (`:374`) — a listing's "see page 2 for financials", "Call now", "Must sell" is neither; the deal-scout focus even requires following browse→detail links. Round-1 live A/B already found 6/6 imperatives kept in the writer. Sound, reasoned.
- The 3-consecutive-search-failure breaker: fires only on thrown searches; an honest run against a healthy provider never trips it, and it does not count against the iteration cap (the refusal is a free tool result — one more free iteration per refused call, but the model is told to stop). Sound.
- The two `nudges`: only when `turnsUsed === 0`; a diligent researcher never sees them. Sound.
- `CHECKPOINT_MAX_PAGES=60` (last 60) vs dossier first-14: only diverges on a resume of a >60-page job; Florida comprehensive lands ~45. Noted, not a finding today.
