## M-C4 · raw hrefs, no protocol allowlist / `tel:` dead link — DOWNGRADED (P2 hygiene)
- Why: the three viewer sites (`ReportViewer.tsx:220/230/321`) and three PDF sites (`report-html.ts:252/289/314`) do emit `javascript:`/`data:` hrefs (flipped `it.fails`: all fail for the stated reason). What a click does, **measured in headless Chrome 151 via puppeteer-core** (`scratchpad/c3c4/click.mjs`) on the exact anchors: `javascript:void(document.title=…)` and `javascript:document.write(<h1 id=pw>)` with `target="_blank" rel="noreferrer"` → one new `about:blank` tab, `location.origin "null"`, `opener null`, title `""`, body empty — the script does NOT run, SPA title/DOM untouched; `data:text/html,<script>…` → no tab at all (Chrome blocks top-frame `data:` navigation); control with NO target → runs in the SPA document (`#pw` written, title cleared). Spec reasoning for Safari: `noreferrer` ⇒ noopener ⇒ new top-level traversable with no creator (opaque origin) ⇒ "navigate to a javascript: URL" returns when the initiator origin is not same origin-domain with the target's document ⇒ blank tab; WebKit enforces the same check. React 18.3.1 verified: `sanitizeURL` (`react-dom.development.js:650-657`) only `error()`s once in DEV, never blocks (React 19 replaces the href with a throwing stub — an upgrade would neutralize these sites for free). The admin viewer has NO raw href sites (only the react-markdown `a` override, `apps/admin/src/components/ReportViewer.tsx:165`) so the admin token is not exposed. PDF: link annotation with a `javascript:` URI action — inert in Chromium's viewer/Preview/Acrobat (reasoned). `tel:`/`mailto:` are hypothetical: `MARKDOWN_DIRECTIVE` (`prompt.ts:50-54`) explicitly invites `[label](https://real-url)`; the two real Florida comprehensive reports carry 377 Markdown links + 399 url fields — 0 `mailto:`, 0 `tel:`, 0 phone numbers, 0 emails (368 https, 11 **http**, 2 malformed `httpshttps://`).

Damage: a model-authored `javascript:`/`data:` "source ↗" link is a dead link (blank tab / nothing) — the same loss as any wrong URL; no script reaches the SPA, the share page or the PDF, and the only thing standing between "dead link" and "script in the SPA's origin" is `target="_blank" rel="noreferrer"` on three anchors (pinned by the refute test).
